# IIC 离线语音控制

在现有 quattro 工程增加亚博 CI1302 / STC8H 语音模块支持。沿用现有
`processCommand()` 动作入口，保留 Wi-Fi、网页、舵机校准及步态实现。
本次没有修改手机 App，也没有增加尚无硬件采样条件的电量数值。

## 接线

先断电，安装好 ESP32 开发板，再接语音模块的 IIC 口：

| 语音模块 | 机器人 |
| --- | --- |
| SDA | D21 对应的 S 信号针（GPIO21） |
| SCL | D22 对应的 S 信号针（GPIO22） |
| GND | ESP32 / 扩展板 GND |
| 5V | 已测量确认的稳定 5V 电源 |

不要把 SDA / SCL 插到三排接口的 V 或 G 排。扩展板上 VCC、VIN 或可切换
V 排不能仅凭名称认定为 5V；先测量。保留现有舵机电源跳帽设置。
官方给出的同款语音模块可直连 3.3V ESP32 的 IIC，不要求加 TXS0108E；
若更换模块版本、或实测空闲 SDA/SCL 为 5V，应先确认其原理图并转换电平。
UART 接口无需同时连接。线尽量短，模块与主控必须共地。

## 功能与口令编号

默认接收厂家 V3 协议，7 位地址 0x2B，结果寄存器 0x64，读取 1 字节。
0x00 表示未识别。不要使用表格的行号或“语义标签”代替协议编号。

| 协议 ID | 厂家 V3 英文词条 | 执行动作 |
| --- | --- | --- |
| 0x01、0x02 | ROBOT-STOP、STOP | 归位 home |
| 0x03 | ROBOT-SLEEP | 归位 home；不会断开舵机电源 |
| 0x04 | GO-AHEAD | 前进，沿用网页的一次动作参数 |
| 0x05 | BACK | 后退 |
| 0x06 | TURN-LEFT | 左转 |
| 0x07 | TURN-RIGHT | 右转 |
| 0x21 | BACK-TO-ORIGIANL | 归位；不是导航返回出发位置 |

中文出厂固件可尝试其预置的“前进、后退、左转、右转、停车”等对应口令，
但实际唤醒词、口令文本和编号以所用模块的固件词表为准。
此次可获取并核对的是厂家英文 V3 协议表，尚未在用户中文模块上验证。
常见中文默认唤醒词为“小亚小亚”；若已改词库，使用修改后的唤醒词。
本次不会给语音模块烧录或修改词库。

不认识的 ID 只打印到串口，不触发动作。跳舞、打招呼等网页功能保留；
若要新增对应语音口令，需先在语音模块词库配置其输出 ID，再在
`VoiceCommands.h` 的映射中添加相应动作，不能只修改 ESP32 就产生新词条。

## 文件与执行流程

- `VoiceConfig.h`：开关、SDA/SCL、地址、寄存器和周期。
- `VoiceIic.h/.cpp`：BSP 层，独占 Wire，由 Arduino 主循环调用。
- `VoiceCommands.h`：将厂家口令 ID 映射成现有命令字符串。
- `quattro.ino`：初始化并调用语音接收，沿用原有 `processCommand()`。

主循环顺序：网页请求处理 → 语音轮询 → 已有有限动作。
没有新增 RTOS 任务、中断或第二个舵机控制者。
机器人和语音在 Wi-Fi 初始化之前完成初始化，Wi-Fi 失败不禁用离线语音。
STA 模式尝试连接期间仍需等待初始化结束。

每 50ms 最多读取一次；总线超时 25ms；读失败后每秒重试。
重连首次结果丢弃，防止存留口令导致突然动作。
同一非零编号持续出现时只执行一次，读到 0 后允许同一编号再次执行，
不同编号也允许立即切换。若某一固件持续返回旧 ID 且始终不回 0，
连续相同口令会被抑制，需要按其真实寄存器清除机制适配，不能用定时重放代替。

**动作仍为原来的阻塞实现。动作期间网页和语音处理会延迟；停止口令需等
当前动作结束后才可能处理，不能作为即时急停。模块也不保证缓存期间所有口令。**
不会自动持续行走，不会累计排队多个步态。

## 编译和首次验证

1. Arduino IDE 打开本目录 `quattro.ino`，开发板选择 **ESP32 Dev Module**。
2. 依赖 **ESP32Servo、ArduinoJson**；Wire 由 ESP32 开发板包自带。
3. 编译并上传。本文配套构建使用 esp32 core 3.3.12、ESP32Servo 3.2.1、ArduinoJson 7.4.3。
4. 串口监视器使用 **9600**，等待 `[Voice] Module connected`。
5. 首次测试架空机器人，先唤醒模块，再逐条测试前进、后退和转向。
6. 串口会打印 `[Voice] ID=0x4 -> forward`；若只打印 unmapped，
   记录编号并对照实际词库调整 `VoiceCommands.h`。
7. 不接语音模块时，原网页 / App 控制仍应可用。

串口出现 Waiting 但一直不出现 connected：检查共地、5V、D21/D22 的 S 排、
SDA/SCL 是否接反，及模块是否为厂家 0x2B / 0x64 固件。
诊断只读不会替模块改地址或固件。
